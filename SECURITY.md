# Security Policy

## Do not submit secrets

Never include credentials, API keys, tokens, cookies, private URLs, internal configuration, customer data, or unpublished implementation details in issues, pull requests, screenshots, examples, or support requests. Use synthetic examples only.

## Reporting a concern

For security or disclosure concerns, contact the repository owner through the GitHub profile or the approved PBT-G contact channel listed on the official product site.

Do not include secrets or sensitive material in the first message. Report only the minimum information needed to explain the concern. If sensitive handling is required, request a secure channel first.

## Scope and limitations

This documentation pack is educational and operational guidance. It does not perform a complete security review, certify a deployment, or guarantee that a server, extension, or workflow is secure. Users remain responsible for their own threat modeling, access controls, review process, and incident response.

## Disclosure handling

Do not publicly disclose a suspected vulnerability until the repository owner has acknowledged the report and agreed on a disclosure plan.
